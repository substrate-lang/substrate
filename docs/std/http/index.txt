;; std/http
;; HTTP/1.1 messages, parsed and written. The parser calls on-head, then on-body for each piece of the body, then
;; on-end, for each message it is fed. Header names are lowercased, and the head's names and values last until on-end.

std/http/checks       Checks for a server's list, run before its handler: cross-origin protection, after Go's CrossOriginProtection; security headers, Helmet's; CORS, after Express's cors; rate limits, a token bucket for each client's address, after Go's x/time/rate; and allowed hosts, after Django's ALLOWED_HOSTS.
std/http/conditional  Conditional requests, RFC 9110's preconditions checked in its order, as Go's ServeContent checks them.
std/http/cookie       Cookies (RFC 6265, with SameSite and the name prefixes of its revision), after Go's net/http.
std/http/form         Forms read into types.
std/http/http         HTTP/1.1 messages, parsed and written.
std/http/multipart    multipart/form-data bodies (RFC 7578), after Go's mime/multipart.
std/http/route        Routes after Go's ServeMux, written as s-expressions with typed parameters.
std/http/server       An HTTP/1.1 server over net.
std/http/session      Sessions in a signed cookie, after Flask's: the session's bytes, the second they were signed, and an HMAC-SHA256 of both, each in base64url and joined by dots, as itsdangerous signs.
std/http/sse-client   Server-sent events read as the HTML standard's EventSource reads them, over the fetch module, so on a page or a server alike.
std/http/sse          Server-sent events, the HTML standard's event streams.
std/http/static       Files: http-send-file! answers with a file under the root, as Flask's send_from_directory does, and http-static! with the file at the request's path, a directory's index.html, or a redirect adding a final slash.
std/http/test         Requests to a server through a connection without a socket, after Go's httptest.
std/http/token        API tokens: random, shown to their owner once, kept as their SHA-256, and presented in an Authorization: Bearer header (RFC 6750).
std/http/url          The parts of a request's target: its path and query, percent-decoding and encoding, a path's segments, and the application/x-www-form-urlencoded format of queries and form bodies, after the WHATWG URL Standard.
std/http/websocket    WebSocket servers (RFC 6455).
